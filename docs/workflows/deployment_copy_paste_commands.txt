Energy Report deployment copy-paste commands
============================================

Use this plain text file for terminal copy/paste.
Do not copy long commands from the PDF when a command contains long URLs,
heredocs, or line continuations.

Current recommended operator flow
---------------------------------

B1. Fresh bootstrap + month-end smoke for 2025-05-31
B2. Change anchor to Sunday 2025-05-18 and run again
B3. Reset anchor back to blank scheduled mode
B4. Only after B3, install or adjust systemd timer
B5. Use the helper commands below for update / clean reinstall / rollback

Important notes
---------------

- Default final output dir: /srv/energy-report-output
- Default staging dir during runtime: /srv/energy-report-output/_staging
- After a successful run, staging files are auto-cleaned and the empty `_staging` folder is removed
- The one-command bootstrap below intentionally uses the deploy branch:
  deploy/stable
- Bootstrap now forces the checkout/clone to the latest remote tip of the selected
  branch/ref during deploy
- That branch currently contains deploy-flow fixes newer than the older reviewed
  tag v4.3.0-dev
- B1 intentionally does NOT install systemd yet, because the anchor is pinned for
  smoke testing
- Only install or enable the timer after B3 has restored:
  REPORT_ANCHOR_DATE=
- Scheduled production expects host timezone Asia/Ho_Chi_Minh unless you
  intentionally deploy another timezone
- The bootstrap flow is meant to support 2 modes:
  - non-interactive flags for curl|bash / automation
  - interactive prompts for a local script run on a desktop/operator host
- In interactive mode, passed flags should win and only missing values should be asked
- Interactive runs should end with a summary/confirmation before the real work starts
- Bootstrap can now optionally install/start the Web UI service too via:
  --install-webui --web-host 0.0.0.0 --web-port 8000

Interactive wizard entrypoint
-----------------------------

Prefer a local file for the interactive mode:

curl -fsSL -o bootstrap_ubuntu_host.sh "https://raw.githubusercontent.com/trantuyen1991/ETL_EMS_REPORT/deploy/stable/deploy/bootstrap_ubuntu_host.sh"
chmod +x bootstrap_ubuntu_host.sh
sudo ./bootstrap_ubuntu_host.sh --interactive --reset-project


B1 - Fresh bootstrap + month-end smoke (Daily + Monthly)
--------------------------------------------------------

curl -fsSL "https://raw.githubusercontent.com/trantuyen1991/ETL_EMS_REPORT/deploy/stable/deploy/bootstrap_ubuntu_host.sh" | sudo bash -s -- --deploy-ref deploy/stable --mysql-host 192.168.100.217 --mysql-database ems_db --mysql-user admin --anchor-date 2025-05-31 --output-dir /home/trantuyen/Reports --reset-project

Optional same-host Web UI install during bootstrap:

curl -fsSL "https://raw.githubusercontent.com/trantuyen1991/ETL_EMS_REPORT/deploy/stable/deploy/bootstrap_ubuntu_host.sh" | sudo bash -s -- --deploy-ref deploy/stable --mysql-host 192.168.100.217 --mysql-database ems_db --mysql-user admin --anchor-date 2025-05-31 --output-dir /home/trantuyen/Reports --reset-project --install-webui --web-host 0.0.0.0 --web-port 8000

Check what was deployed:

sudo -u energy-report -H bash -lc 'cd /srv/energy-report && git rev-parse --short HEAD'
sudo grep '^REPORT_ANCHOR_DATE=' /srv/energy-report/config/.env
OUTPUT_ROOT="$(sudo grep '^OUTPUT_DIR=' /srv/energy-report/config/.env | cut -d= -f2-)"
OUTPUT_ROOT="${OUTPUT_ROOT:-/srv/energy-report-output}"
find "$OUTPUT_ROOT" -path "$OUTPUT_ROOT/_staging" -prune -o -type f -print | sort | tail -n 30

Expected idea for B1:
- script prompts securely for MySQL password if it was omitted and the operator has a TTY
- bootstrap warns if host timezone is not Asia/Ho_Chi_Minh
- Daily artifacts for 2025-05-31 under "$OUTPUT_ROOT"/2025_05/
- Monthly artifacts for 2025-05-31 under "$OUTPUT_ROOT"/2025_05/
- Temporary print files are auto-cleaned after successful copy-back
- If OUTPUT_DIR lives under /home/<user>/..., bootstrap also prepares ACL so energy-report can write there and the home owner can open/manage generated files
- No timer installed yet

----------------------------

sudo sed -i 's|^REPORT_ANCHOR_DATE=.*|REPORT_ANCHOR_DATE=|' /srv/energy-report/config/.env

Timezone preflight before scheduled production
----------------------------------------------

timedatectl
sudo timedatectl set-timezone Asia/Ho_Chi_Minh

Only change timezone if the host is meant to follow Vietnam local time.


B4 - Install systemd service and timer only after B3
----------------------------------------------------

cd /srv/energy-report
sudo ./deploy/systemd/install_systemd_units.sh

Check service and timer:

sudo systemctl status energy-report-etl.service --no-pager
sudo systemctl status energy-report-etl.timer --no-pager
systemctl list-timers energy-report-etl.timer --all
journalctl -u energy-report-etl.service -n 100 --no-pager
OUTPUT_ROOT="$(sudo grep '^OUTPUT_DIR=' /srv/energy-report/config/.env | cut -d= -f2-)"
OUTPUT_ROOT="${OUTPUT_ROOT:-/srv/energy-report-output}"
find "$OUTPUT_ROOT" -path "$OUTPUT_ROOT/_staging" -prune -o -type f -print | sort | tail -n 30


B4.1 - Optionally install/start the Web UI service
--------------------------------------------------

cd /srv/energy-report
sudo ./deploy/systemd/install_systemd_units.sh --with-web --web-host 0.0.0.0 --web-port 8000
curl -fsS http://127.0.0.1:8000/health
curl -I http://127.0.0.1:8000/reports
sudo systemctl status energy-report-web.service --no-pager
journalctl -u energy-report-web.service -n 100 --no-pager

If ETL timer was already installed and you only want Web UI later:

cd /srv/energy-report
sudo ./deploy/systemd/install_systemd_units.sh --web-only --web-host 0.0.0.0 --web-port 8000
curl -fsS http://127.0.0.1:8000/health


B4.2 - Change the timer schedule later
--------------------------------------

sudo nano /etc/systemd/system/energy-report-etl.timer

Find this line:
OnCalendar=*-*-* 23:00:00

After editing, reload and restart the timer:

sudo systemctl daemon-reload
sudo systemctl restart energy-report-etl.timer
systemctl list-timers energy-report-etl.timer --all


B5 - Update to the latest deploy branch
---------------------------------------

cd /srv/energy-report
sudo -u energy-report git fetch origin
sudo -u energy-report git checkout deploy/stable
sudo -u energy-report git pull --ff-only origin deploy/stable
sudo -u energy-report ./venv/bin/pip install -r requirements.txt
sudo -u energy-report ./venv/bin/python -m src.main

If systemd unit files changed in the repo, re-install them:

cd /srv/energy-report
sudo ./deploy/systemd/install_systemd_units.sh

If this host also serves Web UI, re-install Web UI together:

cd /srv/energy-report
sudo ./deploy/systemd/install_systemd_units.sh --with-web --web-host 0.0.0.0 --web-port 8000

Check the current deployed commit:

cd /srv/energy-report
sudo -u energy-report git log -1 --oneline


Clean reinstall from zero
-------------------------

Stop timer/Web UI first if they already exist:

sudo systemctl disable --now energy-report-etl.timer || true
sudo systemctl disable --now energy-report-web.service || true
sudo rm -f /etc/systemd/system/energy-report-etl.service /etc/systemd/system/energy-report-etl.timer /etc/systemd/system/energy-report-web.service || true
sudo systemctl daemon-reload

Remove project and outputs:

sudo rm -rf /srv/energy-report /srv/energy-report-output

Then run B1 again.


Production-ready quick sign-off
-------------------------------

timedatectl
sudo grep '^REPORT_ANCHOR_DATE=' /srv/energy-report/config/.env
sudo systemctl status energy-report-etl.timer --no-pager
sudo systemctl status energy-report-etl.service --no-pager
curl -fsS http://127.0.0.1:8000/health || true

Roll back and run an older version/tag
--------------------------------------

Example: run the older reviewed tag v4.3.0-dev

cd /srv/energy-report
sudo systemctl disable --now energy-report-etl.timer || true
sudo -u energy-report git fetch --tags origin
sudo -u energy-report git checkout --force v4.3.0-dev
sudo -u energy-report ./venv/bin/pip install -r requirements.txt

If the old tag complains about missing Sensor Monitoring outline icons, apply the fallback links:

sudo -u energy-report bash -lc '
set -e
cd /srv/energy-report/src/templates/assets/icon/outline
ln -sf ../sensor/capacity.svg snowflake.svg
ln -sf ../sensor/flow.svg wind.svg
ln -sf ../steam.svg flame.svg
ln -sf ../water.svg droplet.svg
ln -sf ../energy.svg activity.svg
ln -sf ../sensor/power.svg bell.svg
ln -sf ../sensor/pressure.svg gauge.svg
ln -sf ../sensor/temperature.svg thermometer.svg
ln -sf ../sensor/power.svg alert-circle.svg
ln -sf ../sensor/power.svg circle-check.svg
'

Set a smoke anchor and run the old version once:

sudo sed -i 's|^REPORT_ANCHOR_DATE=.*|REPORT_ANCHOR_DATE=2025-05-31|' /srv/energy-report/config/.env
cd /srv/energy-report
sudo -u energy-report ./venv/bin/python -m src.main
OUTPUT_ROOT="$(sudo grep '^OUTPUT_DIR=' /srv/energy-report/config/.env | cut -d= -f2-)"
OUTPUT_ROOT="${OUTPUT_ROOT:-/srv/energy-report-output}"
find "$OUTPUT_ROOT" -path "$OUTPUT_ROOT/_staging" -prune -o -type f -print | sort | tail -n 30

When done, return to the current deploy branch:

cd /srv/energy-report
sudo -u energy-report git checkout deploy/stable
sudo -u energy-report git pull --ff-only origin deploy/stable
sudo -u energy-report ./venv/bin/pip install -r requirements.txt
sudo sed -i 's|^REPORT_ANCHOR_DATE=.*|REPORT_ANCHOR_DATE=|' /srv/energy-report/config/.env
