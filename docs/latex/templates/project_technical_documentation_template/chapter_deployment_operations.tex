\section{Vai trò của chapter deployment and operations}

Chapter này trả lời nhóm câu hỏi thực tế khi đem project sang một host Ubuntu / \texttt{systemd} mới:

\begin{enumerate}[label=-]
\item clone và bootstrap theo baseline nào;
\item các giá trị runtime nào bắt buộc phải thay theo từng hệ thống;
\item có thể copy-paste những block nào để giảm thao tác tay;
\item nên manual smoke ra sao trước khi bật scheduler;
\item cài và xác nhận \texttt{systemd} service / timer thế nào để vận hành ổn định.
\end{enumerate}

Nội dung chương này phải được giữ đồng bộ với \texttt{docs/workflows/deployment\_runbook.md} vì đó là nguồn operator-facing chi tiết nhất cho thao tác triển khai thật.

\section{Recommended deployment baseline}

Baseline triển khai đang được khuyến nghị cho dự án là:

\begin{enumerate}[label=-]
\item host Ubuntu có \texttt{systemd};
\item service account \texttt{energy-report};
\item project root \texttt{/srv/energy-report};
\item một \texttt{venv} mới được tạo trực tiếp trên host;
\item Chrome hoặc Chromium hiện diện để PDF export chạy được;
\item output path writable và không nằm dưới hidden path.
\end{enumerate}

Các guardrail bootstrap cần giữ:

\begin{enumerate}[label=-]
\item không copy \texttt{venv/} từ máy cũ sang máy mới;
\item chỉ dùng sample \texttt{systemd} units trực tiếp nếu host bám đúng baseline user/path;
\item nếu host phải chạy theo giờ Việt Nam, cần xác nhận host timezone trước khi bật timer;
\item giữ rõ ranh giới giữa canonical output path và staging path dùng cho PDF export.
\end{enumerate}

\section{Operator-first full bootstrap flow}

Flow dưới đây được viết cho đúng baseline khuyến nghị của dự án. Nếu host khác baseline, operator phải chỉnh lại user, group, project root, output path, và \texttt{systemd} sample files cho đồng bộ trước khi chạy.

\subsection{Các giá trị cần thay theo từng host}

Trước khi paste các block bên dưới, người cài chỉ cần thay các giá trị host-specific sau:

\item \texttt{MYSQL\_DATABASE};

Nếu host bám đúng baseline chuẩn, đa số trường hợp chỉ cần thay các giá trị MySQL và đường dẫn lưu output.

\subsection{One-command bootstrap option}

Nếu operator muốn tránh copy nhiều dòng lệnh từ PDF, repo có sẵn script bootstrap:

\begin{enumerate}[label=-]
\item \texttt{deploy/bootstrap\_ubuntu\_host.sh}: script tự động cho Ubuntu host mới;
\item \texttt{docs/workflows/deployment\_copy\_paste\_commands.txt}: bản plain text để copy command an toàn hơn PDF.
\end{enumerate}

Khuyến nghị vận hành là copy one-command từ file \texttt{deployment\_copy\_paste\_commands.txt} hoặc từ raw GitHub text, không copy các block lệnh dài trực tiếp từ PDF vì trình đọc PDF có thể wrap dòng, làm mất dấu \texttt{\textbackslash}, tách \texttt{.deb}, hoặc bỏ sót các dòng sau.

Script bootstrap hiện có thể tự cài package nền, cài Google Chrome \texttt{.deb}, tạo service account, clone repo từ \texttt{deploy/stable}, dựng \texttt{venv}, ghi \texttt{config/.env}, ép PDF browser path sang \texttt{/usr/bin/google-chrome}, auto-cài \texttt{acl} và cấp quyền cho service account nếu \texttt{OUTPUT\_DIR} hoặc \texttt{PRINT\_STAGING\_DIR} nằm dưới \texttt{/home/<user>/...}, kiểm tra icon Sensor Monitoring, chạy manual smoke, và nếu có flag \texttt{--install-systemd} thì cài luôn timer. Trong operator flow chuẩn, B1 smoke mode cố ý chưa cài timer cho đến sau bước restore \texttt{REPORT\_ANCHOR\_DATE=}.

\subsection{Step 1. Chuẩn bị host mới}

\begin{ShellBlock}
sudo apt update
sudo apt install -y \
  git \
  python3 \
  python3-venv \
  python3-pip \
  ca-certificates \
  curl \
  netcat-openbsd \
  poppler-utils

python3 --version
which google-chrome || which chromium || which chromium-browser
timedatectl
# If needed:
# sudo timedatectl set-timezone Asia/Ho_Chi_Minh
\end{ShellBlock}

Block này chỉ mới xác nhận baseline runtime. Host Ubuntu 24.04 thường cài \texttt{chromium} dạng Snap; dạng này có thể lỗi khi chạy headless bằng service account hoặc \texttt{systemd}. Vì PDF export của project ưu tiên \texttt{google-chrome} trước \texttt{chromium}, baseline khuyến nghị là cài Google Chrome bản \texttt{.deb} nếu host chưa có \texttt{google-chrome}.

\begin{ShellBlock}
curl -L -o /tmp/google-chrome.deb \
  https://dl.google.com/linux/direct/google-chrome-stable_current_amd64.deb
sudo apt install -y /tmp/google-chrome.deb

which google-chrome
google-chrome --version

sudo -u "$(whoami)" google-chrome \
  --headless \
  --disable-gpu \
  --no-sandbox \
  --dump-dom about:blank >/tmp/chrome-smoke.html
\end{ShellBlock}

Expected result của Step 1:

\begin{enumerate}[label=-]
\item \texttt{python3 --version} trả về Python 3.12.x trên Ubuntu 24.04;
\item \texttt{which google-chrome} trả về executable path;
\item \texttt{timedatectl} hiển thị timezone đúng với lịch chạy mong muốn;
\item nếu database host đã biết, có thể kiểm tra network bằng \texttt{nc -vz MYSQL\_HOST 3306} trước khi chạy smoke.
\end{enumerate}

\subsection{Step 2. Tạo service account, clone repo, và dựng venv}

\begin{ShellBlock}
sudo useradd --system \
  --no-create-home \
  --home-dir /srv/energy-report \
  --shell /usr/sbin/nologin \
  energy-report || true

sudo mkdir -p /srv
sudo chown energy-report:energy-report /srv
sudo -u energy-report git clone --branch deploy/stable --depth 1 \
  https://github.com/trantuyen1991/ETL_EMS_REPORT.git \
  /srv/energy-report

cd /srv/energy-report
sudo -u energy-report python3 -m venv venv
sudo -u energy-report ./venv/bin/pip install --upgrade pip
sudo -u energy-report ./venv/bin/pip install -r requirements.txt
\end{ShellBlock}

Đây là baseline end-to-end cho host mới. \texttt{--no-create-home} là cố ý: nếu dùng \texttt{--create-home}, Linux sẽ tạo sẵn \texttt{/srv/energy-report} với các dotfiles mặc định và lệnh \texttt{git clone ... /srv/energy-report} sẽ fail vì thư mục đích đã tồn tại và không rỗng. Nếu cần rollback đúng reviewed snapshot cũ, chỉ thay target clone branch bằng \texttt{v4.3.0-dev} một cách có chủ đích.

Nếu cần reset riêng Step 2 để chạy lại từ đầu trên một host test, dùng block sau. Block này xóa project checkout và user service account, nhưng không xóa output report.

\begin{ShellBlock}
sudo bash -lc 'set -e
rm -rf /srv/energy-report
id energy-report >/dev/null 2>&1 && userdel energy-report || true
useradd --system --no-create-home --home-dir /srv/energy-report --shell /usr/sbin/nologin energy-report
mkdir -p /srv
chown energy-report:energy-report /srv
sudo -u energy-report git clone --branch deploy/stable --depth 1 https://github.com/trantuyen1991/ETL_EMS_REPORT.git /srv/energy-report
cd /srv/energy-report
sudo -u energy-report python3 -m venv venv
sudo -u energy-report ./venv/bin/pip install --upgrade pip
sudo -u energy-report ./venv/bin/pip install -r requirements.txt
'
\end{ShellBlock}

\texttt{venv} phải luôn được tạo lại ngay trên máy đích, không copy từ host khác.

\subsection{Step 3. Ghi \texttt{config/.env} bằng block paste-ready}

Block bên dưới phản ánh operator-first flow hiện tại. Canonical source vẫn là \texttt{docs/workflows/deployment\_runbook.md}, nhưng technical PDF giữ lại block này để người vận hành đọc tài liệu bàn giao vẫn nhìn được đúng mẫu cấu hình cần paste.

\begin{ShellBlock}
sudo tee /srv/energy-report/config/.env >/dev/null <<'EOF'
# --- Change these values to match the target system ---
MYSQL_HOST=__FILL_DB_HOST__
MYSQL_PORT=3306
MYSQL_DATABASE=__FILL_DB_NAME__
MYSQL_USER=__FILL_DB_USER__
MYSQL_PASSWORD=__FILL_DB_PASSWORD__

# --- Change these paths only if your host uses a different storage layout ---
OUTPUT_DIR=/srv/energy-report-output
PRINT_STAGING_DIR=/srv/energy-report-output/_staging

# --- Usually keep these values as-is ---
REPORT_FILENAME=energy_automatic_report
LOG_LEVEL=INFO
WORKSHOP_NAME=ENERGY REPORT
ENERGY_UNIT=kWh

# --- Keep blank in normal scheduled production mode ---
REPORT_ANCHOR_DATE=
EOF

sudo chown energy-report:energy-report /srv/energy-report/config/.env
sudo chmod 640 /srv/energy-report/config/.env
sudo mkdir -p /srv/energy-report/logs /srv/energy-report-output /srv/energy-report-output/_staging
sudo chown -R energy-report:energy-report \
  /srv/energy-report/logs \
  /srv/energy-report-output \
  /srv/energy-report-output/_staging
\end{ShellBlock}

Các điểm bắt buộc phải nhớ khi dùng block này:

\begin{enumerate}[label=-]
\item \texttt{REPORT\_ANCHOR\_DATE} phải để trống trong steady-state scheduled mode;
\item nếu giữ nhầm một anchor date cố định sau smoke test, timer sẽ lặp lại ngày đó thay vì current date thực;
\item \texttt{OUTPUT\_DIR} là canonical final artifact root, với month folders được tạo trực tiếp dưới \texttt{OUTPUT\_DIR/YYYY\_MM/};
\item \texttt{PRINT\_STAGING\_DIR} là staging-only path, nên thường là subfolder riêng như \texttt{/srv/energy-report-output/\_staging};
\item sau khi export thành công, runtime tự xóa staging files của batch hiện tại, prune thư mục \texttt{\_staging} nếu rỗng, và dọn legacy loose report files ở root của \texttt{OUTPUT\_DIR};
\item \texttt{OUTPUT\_DIR} và \texttt{PRINT\_STAGING\_DIR} phải là non-hidden writable paths;
\item với desktop-like host, nên ưu tiên \texttt{/home/<user>/Reports} thay vì Desktop trực tiếp; nếu dùng path dưới \texttt{/home/<user>/...}, bootstrap script hiện có thể auto-cài ACL để service account \texttt{energy-report} ghi được và home owner mở được file report đã sinh;
\item nếu operator đổi các path này thủ công trong \texttt{config/.env} sau bootstrap, cần chạy lại bootstrap hoặc tự áp equivalent \texttt{setfacl} commands;
\item nếu host không dùng baseline \texttt{/srv/energy-report}, block và \texttt{systemd} units phải được chỉnh đồng bộ.
\end{enumerate}

\subsection{Step 5. Manual smoke trước khi bật schedule}

\begin{ShellBlock}
cd /srv/energy-report
sudo -u energy-report ./venv/bin/python -m src.main
OUTPUT_ROOT="$(sudo grep '^OUTPUT_DIR=' /srv/energy-report/config/.env | cut -d= -f2-)"
OUTPUT_ROOT="${OUTPUT_ROOT:-/srv/energy-report-output}"
find "$OUTPUT_ROOT" \
  -path "$OUTPUT_ROOT/_staging" -prune -o \
  -type f -print | sort | tail -n 30
\end{ShellBlock}

Expected baseline behavior:

\begin{enumerate}[label=-]
\item luôn có một batch \textit{daily};
\item \textit{weekly} chỉ xuất hiện khi anchor day là Chủ nhật;
\item \textit{monthly} chỉ xuất hiện khi anchor day là ngày cuối tháng;
\item daily run cũng tạo một workbook Excel theo đúng scope hiện hành;
\item nếu export thành công, month folder dưới \texttt{OUTPUT\_DIR/YYYY\_MM/} có đủ \texttt{view\_html/}, \texttt{pdf\_source\_html/}, \texttt{pdf/}, và daily \texttt{excel/} khi applicable.
\end{enumerate}

Nếu cần deterministic smoke anchors cho Sunday hoặc month-end, operator nên dùng \texttt{docs/workflows/release\_runbook.md} để bám đúng các anchor đã được chấp nhận, thay vì tự đoán ngày kiểm tra.

\subsection{Step 6. Restore scheduled mode sau smoke test}

Nếu đã dùng \texttt{REPORT\_ANCHOR\_DATE} cố định để test month-end hoặc Sunday, phải restore về rỗng trước khi bật timer production.

\begin{ShellBlock}
sudo sed -i 's|^REPORT_ANCHOR_DATE=.*|REPORT_ANCHOR_DATE=|' \
  /srv/energy-report/config/.env
\end{ShellBlock}

\subsection{Step 7. Cài \texttt{systemd} service và timer bằng helper}

\begin{ShellBlock}
cd /srv/energy-report
./deploy/systemd/install_systemd_units.sh
\end{ShellBlock}

Helper script hiện làm các việc sau trong một lần chạy:

\begin{enumerate}[label=-]
\item tự gọi \texttt{sudo} khi cần;
\item backup unit cũ nếu đã tồn tại;
\item copy sample \texttt{service} và \texttt{timer} sang \texttt{/etc/systemd/system/};
\item chạy \texttt{systemctl daemon-reload};
\item chạy \texttt{systemctl enable --now energy-report-etl.timer};
\item in ra timer status và schedule summary.

\section{Logging retention baseline}

Runtime application log được cấu hình trong \TablePath{config/logging.yaml}. Baseline hiện tại dùng \texttt{logging.handlers.RotatingFileHandler} để tránh file log tăng không giới hạn trên host chạy lâu ngày.

\begin{table}[htbp]
	\centering
	\renewcommand{\arraystretch}{1.3}
	\caption{Runtime application log retention baseline}
	\label{tab:deployment_log_retention_baseline}
	\begin{tabularx}{\linewidth}{|>{\RaggedRight\arraybackslash}p{4.0cm}|>{\RaggedRight\arraybackslash}X|}
		\hline
		\textbf{Item} & \textbf{Baseline} \\ \hline
		Config source & \TablePath{config/logging.yaml} \\ \hline
		Runtime log file & \TablePath{logs/app.log} dưới project root của deployment, ví dụ \TablePath{/srv/energy-report/logs/app.log} \\ \hline
		Handler & \texttt{logging.handlers.RotatingFileHandler} \\ \hline
		Max active log size & \texttt{10485760} bytes, xấp xỉ 10 MB \\ \hline
		Backup retention & \texttt{backupCount: 10}, tương ứng \texttt{app.log.1} đến \texttt{app.log.10} \\ \hline
	\end{tabularx}
\end{table}

Log của \texttt{systemd} vẫn nằm trong journal riêng và kiểm tra bằng \texttt{journalctl -u energy-report-etl.service}. Hai nguồn log này bổ sung cho nhau: \texttt{logs/app.log} dùng để đọc log ứng dụng theo file, còn \texttt{journalctl} dùng để kiểm tra service lifecycle, exit code, và lỗi từ timer.

\section{Operational validation checklist}

Trước khi coi host mới là usable cho production-like schedule, nên xác nhận tối thiểu:

\begin{enumerate}[label=-]
\item MySQL credentials đúng và truy cập được dưới service account;
\item browser runtime có sẵn;
\item output path writable;
\item \texttt{logs/} writable và \texttt{config/logging.yaml} đang dùng rotation baseline 10 MB / 10 backups;
\item manual run thành công;
\item service start thủ công thành công;
\item timer đã enabled và hiển thị next run đúng 23:00 theo timezone mong muốn;
\item operator biết rõ block paste-ready nào là canonical source cần dùng lại khi cài host tiếp theo.
\end{enumerate}
